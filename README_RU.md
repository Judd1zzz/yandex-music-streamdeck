## Безопасность

> ⚠️ **Коротко: само использование плагинов вашему аккаунту ничем не грозит. Риск появляется, только если автор плагина недобросовестный: доступ к клиенту позволяет украсть данные входа. Выбирайте проверенный софт, особенно осторожно — с автообновлением.**

**Почему плагины работают через порт отладки.** У Яндекс Музыки нет ни официального API, ни SDK для десктоп-клиента — просьбы о поддержке Stream Deck звучат уже почти семь лет и остаются без ответа. Поэтому плагины для неё работают с клиентом напрямую через порт отладки Chrome DevTools — и этот работал так же, по v2.4.0 включительно. Своим многолетним бездействием Яндекс фактически сам подталкивает пользователей к софту, построенному на отладочном доступе, — в том числе и к потенциально опасному.

**В чём риск.** Порт отладки — это универсальный канал управления: клиент Яндекс Музыки — Electron-приложение, по сути браузер, и через этот порт можно не только нажимать кнопки плеера, но и, например, вытащить cookies и токены вашего аккаунта Яндекса. Порт открыт только локально, извне к нему не подключиться, но подключиться к нему и делать то же самое, что делает плагин, может что угодно на вашем компьютере.

**Как это устроено в этом плагине с v2.5.0.** Этому плагину больше не нужен открытый порт отладки. В поставке есть подписанная библиотека-мост `ym-bridge`, которая общается с Яндекс Музыкой по приватному каналу, существующему только между плагином и клиентом: порт никто не слушает, а значит, через него до клиента не дотянется ничто другое на вашей машине. Обе стороны проверяют друг друга — плагин отказывается грузить мост, подписанный не моим ключом, а мост отказывается обслуживать кого-либо, кроме моего плагина. Проверка работает на отказ: непроверенный файл не загружается никогда.

**Почему автообновление — отдельная история.** Плагин с автообновлением может в любой момент доставить на ваш компьютер любой код. Даже если сегодня он безобиден, недобросовестному автору достаточно одного обновления, чтобы массово увести аккаунты пользователей. Поэтому непроверенный плагин с автообновлением — худшая комбинация: доверять приходится не коду, который вы поставили, а автору — навсегда.

**Про копии этого плагина.** Исходники моего плагина у всех на виду, и именно из него сейчас регулярно заимствуют идеи и функциональность другие проекты: есть зафиксированные случаи переноса конкретных функций один в один. Копия может выглядеть знакомо, но не проходит никакой внешней проверки — что именно приедет вам со следующим её обновлением, не знает никто, кроме автора.

**Как обстоят дела у меня.** Исходный код плагина открыт для чтения и проверки, кроме моста: библиотека `ym-bridge`, код, который она внедряет в клиент, и инжектор для Windows поставляются готовыми и подписанными. Начиная с v2.5.0 библиотека-мост едет в каждом релизе подписанной тем же аппаратным ключом, что и релизы, и плагин сверяет эту подпись перед загрузкой.

**Почему мост закрыт.** Не для того, чтобы что-то от вас скрыть. Мой плагин уже копировали. Проблема с портом отладки, описанная выше, — ровно та причина, по которой я не хочу, чтобы копии моста начали плодиться: форк моста — идеальное место, чтобы встроить вредоносный код, а снаружи он будет выглядеть точь-в-точь как мой. Закрытые исходники здесь — защита от бездумного копирования, и только: мост не виртуализирован протекторами вроде VMProtect, так что специалисты при желании могут разобрать `ym-bridge.dll` / `ym-bridge.dylib` и посмотреть, что он делает. А тот, кто способен его отреверсить, и так достаточно компетентен, чтобы написать свой.

Есть ещё сборка из [Elgato Marketplace](https://marketplace.elgato.com/product/yandex-music-integration-43741c24-1784-4492-be32-c631d7c55829): каждая версия этой сборки перед публикацией проходит ревью Elgato — попасть на маркетплейс «просто так» нельзя, и это ещё один слой защиты. Собственного автообновления в этой сборке нет вовсе: обновления доставляет сам магазин. А автообновление GitHub-сборки принимает только релизы, подписанные моим аппаратным ключом, — как это проверить самому, ниже.

### Как проверить, что релиз собран мной

Начиная с v2.4.0 каждый GitHub-релиз я подписываю лично: файл `SHA256SUMS` с хэшами обоих архивов подписан моим аппаратным ключом — такую подпись нельзя поставить без физического касания ключа, даже угнав мой компьютер или аккаунт GitHub. Автообновление плагина проверяет эту подпись само и молча отклоняет всё, что подписано не мной. Проверить руками (файлы `SHA256SUMS` и `SHA256SUMS.sig` лежат в каждом релизе рядом с архивами):

```bash
curl -sO https://raw.githubusercontent.com/Judd1zzz/yandex-music-streamdeck/main/allowed_signers
ssh-keygen -Y verify -f allowed_signers -I Judd1zzz -n file -s SHA256SUMS.sig < SHA256SUMS
shasum -a 256 -c SHA256SUMS --ignore-missing
```

Первая проверка должна ответить `Good "file" signature for Judd1zzz with ED25519-SK key`, вторая — `OK` напротив скачанного архива (на Windows вместо `shasum` — `sha256sum` из Git Bash). Понадобится OpenSSH 8.2 или новее (встроенный в Windows 10 не подойдёт — берите из Git for Windows).

Библиотека-мост подписана тем же ключом. Чтобы проверить её, распакуйте архив рядом с `allowed_signers` и выполните (на Windows — `ym-bridge.dll` и `ym-bridge.dll.sig`):

```bash
ssh-keygen -Y verify -f allowed_signers -I Judd1zzz -n file -s com.judd1.yandex_music.sdPlugin/bin/ym-bridge.dylib.sig < com.judd1.yandex_music.sdPlugin/bin/ym-bridge.dylib
```

Ответ должен быть тем же: `Good "file" signature for Judd1zzz`.

## Что умеет плагин

### Базовое управление
- **Play/Pause** — ставьте на паузу и продолжайте воспроизведение
- **Вперёд/Назад** — переключайте треки
- **Лайк/Дизлайк** — влияйте на рекомендации "Моей Волны"
- **Перемешивание (Shuffle)** — включайте случайный порядок; кнопка показывает состояние клиента
- **Повтор (Repeat)** — циклическое переключение режима (выкл → все → один трек) со своей иконкой для каждого режима
- **Mute** — выключайте звук, не теряя уровень громкости
- **Запустить Яндекс Музыку** — запускает клиент без отладочных флагов; если он уже подключён — ничего не делает. На Windows нажатие на неё (или на любую кнопку плагина, если не выключено «Разрешить запуск с любой кнопки плагина») ещё и перезапускает зависший клиент, до которого плагин не может достучаться 30 секунд. Идеальный первый шаг для Multi Action

> **Shuffle/Repeat на «Моей Волне»:** плагин ставит режим напрямую через плеер; контекстное меню открывается только как запасной путь. Перемешивание на «Моей Волне» недоступно (это и так лента разных исполнителей), а повтор там переключается только между «выключено» и «повторять трек».

### Громкость
- **Volume +/-** — регулировка громкости на 5% за нажатие
- **Индикатор громкости** — отдельная кнопка, показывающая текущий уровень
- **Проценты громкости в самом клиенте** — плагин дорисовывает точное значение над ползунком Яндекс Музыки
- **Volume Knob (крутилки)** — на устройствах с энкодерами (Ajazz/Mirabox вроде AKP05E Pro): поворот — громкость (шаг настраивается, по умолчанию 5% за тик), нажатие — Mute или Play/Pause (настраивается). На крутилку также можно назначить Play/Pause, Next/Prev, Like/Dislike, Shuffle, Repeat, Mute, «Скачать» и «Запустить Яндекс Музыку» — сработают по нажатию

> **Длинное нажатие:** в коде реализована плавная регулировка при зажатии кнопки, но на некоторых аналогах Stream Deck она может не работать. Судя по всему, это техническое ограничение устройств — событие нажатия приходит только в момент отпускания кнопки. На оригинальном Stream Deck, скорее всего, всё будет нормально, но пока не проверено.

### Информация о треке
- **Обложка + название + исполнитель** — всё на одной кнопке
- **Бегущая строка** — длинные названия автоматически прокручиваются
- **Действие по нажатию** — нажатие на кнопку ставит на паузу/запускает трек (по умолчанию), копирует "Исполнитель - Трек" в буфер обмена или ничего не делает — настраивается
- **Тайм-коды на обложке** — опционально: прошедшее время и длительность поверх обложки
- **Прогресс-бар** — показывает прогресс трека: прошедшее время, длительность или полосу — несколько стилей на выбор

### Discord Rich Presence
- **Текущий трек в профиле Discord** — статус «Слушает» с названием, исполнителем, обложкой и прогрессом
- **Работает из коробки** — включается одним переключателем в настройках, создавать ничего не нужно
- Хотите собственное имя/иконку статуса — впишите свой `Application ID` (опционально)

### Скачивание трека
- **Кнопка «Скачать трек»** на Stream Deck — сохраняет текущий трек в файл
- **Кнопка прямо в плеере Яндекс Музыки** — плагин добавляет кнопку скачивания в плеер-бар клиента, рядом с лайком
- Форматы: **Lossless (FLAC/M4A)** или **MP3 320**, с тегами и обложкой; папка и формат настраиваются

### Видеообложка
- **Фоновое видео в полноэкранном плеере** — если у трека есть фоновое видео, полноэкранный плеер клиента показывает его за обложкой. На паузе видео останавливается и прячется; у треков без видео остаётся обычная обложка
- **Из коробки:** включено; пока играет видео, обложка скрыта и видна при наведении; яркость видео 30%, а при открытой очереди или тексте — 50%; подложка под элементами плеера выключена (если включить: цвет — акцент трека, непрозрачность 25%)
- **Свои эффекты (по желанию):** ползунки размытия, насыщенности, контраста и «Чёрно-белое» для видео, а также размытия, насыщенности и яркости фона под подложкой
- Настраивается в панели настроек → «Возможности» → «Видеообложка»; изменения применяются без перезапуска клиента

### Подробности
Дополнительные сведения прямо на страницах клиента:
- **Альбомы** — полная дата релиза со значком новинки, жанр, число треков и общая длительность
- **Плейлисты** — номера строк, дата создания, число треков и общая длительность, значок приватного плейлиста и «Ещё плейлисты автора»
- **Артисты** — изменение слушателей за месяц, описание, лайки, число альбомов и треков, даты рождения и смерти, настоящие имена, жанры и страны
- **Из коробки:** включено всё, кроме «Даты добавления трека» (плейлисты) и значка «Сгенерировано ИИ» (артисты)
- **Дополнительные запросы к Яндекс Музыке** (включено по умолчанию) — часть сведений требует одного запроса на открытую страницу; запрос идёт через сам клиент к Яндекс Музыке, без третьих сторон, с кэшем на сеанс. Если выключить, показывается только то, что клиент уже держит в памяти: жанр, число треков альбома и плейлиста, значок приватности и номера строк; пункты, которым нужны запросы, помечены «нужны запросы». Этот выключатель не касается значка «Сгенерировано ИИ»: пока значок включён, запрос к `iimuzyka.top` уходит и при выключенных дополнительных запросах
- Настраивается в панели настроек → «Возможности» → «Подробности», группы «Плейлисты», «Альбомы» и «Артисты»; изменения применяются без перезапуска клиента

> ⚠️ **О ваших данных — значок «Сгенерировано ИИ».** По умолчанию значок выключен. Если его включить, этот плагин отправляет ID каждого открытого артиста на сторонний сайт `iimuzyka.top` — без данных аккаунта, cookies и реферера, но сайт видит ваш IP-адрес, как при любом запросе. Выключатель «Дополнительные запросы к Яндекс Музыке» не касается этого значка: пока значок включён, запрос к `iimuzyka.top` уходит и при выключенных дополнительных запросах.

### Управление с телефона
- **Этот компьютер — устройство в приложении Яндекс Музыки** — если включено «Управление этим компьютером с телефона», компьютер появляется в списке устройств приложения Яндекс Музыки на телефоне с тем же аккаунтом: оттуда можно запускать музыку, ставить на паузу, переключать треки и менять громкость
- **По умолчанию выключено** — включается в панели настроек → «Соединение». Play на компьютере, в том числе с деки, забирает музыку у телефона; выключите переключатель — и компьютер сразу пропадёт из списка на телефоне. Если же выйти из Stream Deck или удалить этот плагин, режим держится до перезапуска клиента
- **Плагин сам ничего не запрашивает** — этот режим в клиенте для компьютера уже есть, но выключен. Плагин только включает его внутри клиента и токен не читает; клиент общается с собственным сервисом Яндекс Музыки так же, как мобильное приложение

> ⚠️ Режимом Яндекс управляет на своей стороне и может закрыть или изменить его. Тогда переключатель перестанет работать до обновления этого плагина.

### Статистика прослушивания
- **Хранится локально** — прослушанные треки, сессии и их длительность, аптайм, загрузки и их объём, активность по часам и дням недели, топ артистов и треков, нажатия по каждому действию. Смотреть за 7 или 30 дней — в панели настроек → «Аналитика» → «Статистика»
- **Где лежит** — начиная с v2.5.0 в каталоге данных ОС, вне папки плагина: `~/Library/Application Support/com.judd1.yandex_music/stats.json` на macOS, `%APPDATA%\com.judd1.yandex_music\stats.json` на Windows. Сборки с GitHub, из StreamDock Store и из Elgato Marketplace пишут в этот же файл
- **Переживает обновления** — ни автообновление плагина, ни обновление из магазина, ни переустановка её не трогают. При первом запуске v2.5.0 старый `logs/stats.json` из папки плагина копируется туда, а старый файл переименовывается в `logs/stats.json.migrated`
- Лог (`logs/plugin.log`) и сохранённый путь к клиенту остаются в папке плагина

### Автообновление
- **Нет в сборке из Elgato Marketplace** — там обновления приходят из Marketplace после ревью каждой версии командой Elgato — это может занять несколько дней
- **Проверка обновлений при запуске** — новые версии подтягиваются с GitHub автоматически
- **Каждое обновление проверяется подписью** — плагин принимает только релизы, подписанные моим аппаратным ключом ([как это устроено](#как-проверить-что-релиз-собран-мной))
- Функция новая и в бою пока не обкатана. Если обновление не доехало — просто скачайте свежий релиз руками, как раньше: ручная установка всегда работает
- Обновления скачивает и записывает сам плагин, поэтому разовый шаг с `xattr` из инструкции по установке на macOS повторять не придётся

### Техническая база
- **Event-Driven архитектура** — мгновенный отклик, минимальная нагрузка в простое
- **Устойчивость к обновлениям** — состояние трека читается из внутреннего стора плеера, а DOM-селекторы (`data-test-id` и фолбэки) служат страховкой
- **Нативный бинарь** — Rust (`bin/ym-plugin`) и рядом подписанная библиотека `ym-bridge`, не нужен Python или Node.js

### 3. Запускайте Яндекс Музыку как обычно

Плагин связывается с клиентом через библиотеку-мост `ym-bridge`, которая лежит рядом с ним. Мост загружается в клиент и открывает приватный канал, доступный только плагину: порт не открывается, а клиенту не нужны ни флаги запуска, ни специальные ярлыки. Перед загрузкой моста плагин сверяет его подпись — подробнее в разделе [Безопасность](#безопасность).

- **Windows:** плагин подключается к уже открытой Яндекс Музыке — обычно без перезапуска; если мост загрузился, но не отвечает, плагин перезапустит клиент, а если мост так и не загрузился, клиент перезапустит нажатие кнопки.
- **macOS:** мост можно загрузить только в момент старта клиента, поэтому клиент, открытый без него (например, из Dock), один раз перезапускается. Занимает пару секунд, трек и очередь клиент восстанавливает сам.
- **Клиент вообще не запущен?** Нажмите любую кнопку плагина или «Запустить Яндекс Музыку» — плагин запустит клиент сам.
- **Клиент установлен в нестандартное место?** Укажите путь один раз: панель настроек → «Соединение» → «Путь к клиенту».

Не хотите, чтобы плагин сам перезапускал клиент? Выключите «Запускать и перезапускать клиент автоматически» в панели настроек (вкладка «Соединение»): тогда запущенный клиент плагин будет перезапускать только по нажатию своих кнопок. Закрытый клиент плагин запускает только по нажатию кнопки — при любом положении этого переключателя.

Остался специальный ярлык или приложение-лаунчер от прошлых версий? Он больше не нужен — удалите его и запускайте Яндекс Музыку как обычно.

## Режим Ynison

До v2.4.0 в настройках кнопки был переключатель «Тип управления» с экспериментальным режимом Ynison. В Rust-версии этот режим был заглушкой, поэтому в v2.5.0 его больше нет: кнопки, где он был выбран, теперь управляют клиентом на компьютере, как все остальные. Python-версия в [`python_deprecated/`](python_deprecated/) с локальным сервером `api_for_plugin` оставлена для сверки — см. «Техническое устройство» ниже.

Управление этим компьютером с телефона — другая функция, и отдельный сервер ей не нужен, см. [Управление с телефона](#управление-с-телефона).

## Техническое устройство

<details>
<summary><b>☁️ API-сервер для Ynison</b></summary>

Этим сервером пользуется только Python-версия из [`python_deprecated/`](python_deprecated/); Rust-плагин к нему не обращается.

Это отдельный FastAPI-сервер, который выступает прокси между плагином и протоколом Ynison. Плагин общается с ним по WebSocket и HTTP, а сервер уже поддерживает соединение с Яндексом.

#### Архитектура

```
┌─────────────────────┐      WebSocket       ┌───────────────────────┐
│   Stream Deck       │ ◀──────────────────▶ │   api_for_plugin      │
│   Plugin            │      /ws             │   (FastAPI)           │
└─────────────────────┘                      └───────────────────────┘
                                                       │
                                    ┌──────────────────┴──────────────────┐
                                    │                                     │
                                    ▼                                     ▼
                       ┌────────────────────────┐          ┌──────────────────────────┐
                       │   Ynison WebSocket     │          │   Yandex Music REST API  │
                       │   wss://ynison.music.  │          │   api.music.yandex.net   │
                       │   yandex.ru            │          │   (лайки, метаданные)    │
                       └────────────────────────┘          └──────────────────────────┘
```

#### Компоненты

| Файл | Что делает |
|------|------------|
| `main.py` | FastAPI-приложение, эндпоинты `/ws`, `/control/{action}`, `/check_token` |
| `manager.py` | Менеджер сессий. `SessionManager` держит активные `YnisonSession` для каждого токена |
| `yandex_api.py` | REST-клиент для Яндекс Музыки: лайки, дизлайки, метаданные треков |
| `ynison/player.py` | Реализация Ynison-плеера: подключение, команды, обработка state |
| `ynison/client.py` | Низкоуровневый WebSocket-клиент для Ynison |
| `ynison/models/` | Pydantic-модели для сериализации всех сообщений протокола |
| `utils/auth.py` | Хранилище токена и device_id для аутентификации |

#### Эндпоинты

**WebSocket `/ws`**
- Заголовок `Authorization: <token>`
- При подключении автоматически стартует Ynison-сессия для этого токена
- Получает real-time обновления состояния плеера (JSON)

**POST `/control/{action}`**
- Действия: `play_pause`, `next`, `prev`, `like`, `dislike`
- Заголовок `Authorization: Bearer <token>` или `Authorization: <token>`
- Возвращает `{"status": "ok"}`

**GET `/check_token`**
- Проверяет валидность токена
- Возвращает `{"valid": true}` или `{"valid": false}`

#### Сильные стороны

- **Многопользовательский режим** — один сервер на несколько пользователей, ленивые сессии
- **Обогащение метаданных** — Ynison даёт только ID, сервер дозапрашивает обложки и имена через REST
- **Синхронизация лайков** — при старте загружаются списки лайкнутых/дизлайкнутых
- **Отказоустойчивость** — автореконнект, таймауты, graceful shutdown
- **Pydantic-модели** — весь протокол типизирован и валидируется

#### Запуск

```bash
cd api_for_plugin
pip install -r requirements.txt
python main.py
```

Сервер запустится на `http://0.0.0.0:8000`

└─────────────────────┘                     │   └───────────────────────────────┘   │
                                            └───────────────────────────────────────┘
```

#### Поток данных

1. **Подключение:**
   - На macOS библиотека `ym-bridge` загружается в клиент в момент его старта; на Windows плагин подключается к уже запущенному клиенту
   - Мост открывает приватный канал, доступный только плагину, — TCP-порт не открывается
   - Перед загрузкой моста плагин сверяет его подпись, а мост, в свою очередь, обслуживает только тот бинарь плагина, который узнаёт

2. **Пульт внутри клиента:**
   - Плагин внедряет в Яндекс Музыку свой код — единый пульт
   - Пульт читает состояние плеера из внутреннего стора приложения и сообщает только то, что изменилось
   - «Видеообложка», «Подробности» и управление с телефона — части того же пульта: их настройки приходят из панели настроек по тому же каналу и применяются без перезапуска клиента

3. **Отправка команд:**
   - Нажатия кнопок доходят до пульта по тому же приватному каналу
   - Пульт действует напрямую через плеер: например, перемешивание и повтор ставятся без открытия контекстного меню, а путь через меню остаётся запасным

#### Компоненты плагина

Бэкенд — Rust workspace в `com.judd1.yandex_music.sdPlugin/src/`:

| Крейт | Что делает |
|-------|------------|
| `crates/ym-launch/` | Поиск, запуск и перезапуск клиента |
| `crates/ym-remote-controller/` | Канал к клиенту через мост: внедряет пульт, отправляет команды, принимает состояние |
| `crates/ym-model/` | Модели состояния (`serde`): `MediaState`, `TrackData`, `PlaybackData` |
| `crates/ym-core/` | Действия (кнопки), оркестратор, шина событий |
| `crates/ym-render/` | Рендеринг иконок и динамических кнопок |

Библиотека `ym-bridge` (`bin/ym-bridge.dll` / `bin/ym-bridge.dylib`) — закрытый компонент: она поставляется готовой и подписанной рядом с бинарём плагина (см. [Безопасность](#безопасность)).

> Код, который плагин внедряет в клиент, не только читает состояние и нажимает кнопки за плагин — он ещё и **дополняет интерфейс клиента**: добавляет в плеер-бар Яндекс Музыки кнопку скачивания, оформленную под родные кнопки (кроме сборки из Elgato Marketplace), показывает фоновое видео в полноэкранном плеере ([Видеообложка](#видеообложка)) и дописывает сведения на страницы альбомов, плейлистов и артистов ([Подробности](#подробности)).

#### Почему это надёжно

- **Чтение из внутреннего стора плеера** — название, исполнитель, обложка, прогресс, громкость берутся из состояния приложения, а не из «хрупкой» вёрстки
- **DOM-фолбэки** — если стор недоступен, в ход идут многослойные селекторы (`data-test-id` и альтернативы)
- **Delta-обновления** — передаются только изменившиеся поля, не весь стейт
- **Кнопка показывает реальное состояние** — Play/Pause и Mute сразу следуют за обновлениями самого клиента; кнопка громкости показывает уровень, который сообщает плеер
- **Автореконнект** — при разрыве соединения плагин переподключается автоматически

## Проблемы?

| Симптом | Что делать |
|---------|------------|
| Кнопки не реагируют | Нажмите любую кнопку плагина или «Запустить Яндекс Музыку» — плагин сам запустит клиент; на macOS клиент, открытый без моста, один раз перезапускается. Если «Запускать и перезапускать клиент автоматически» выключено, запущенный клиент плагин перезапускает только по нажатию кнопки |
| «Рядом с плагином нет библиотеки-моста» | Возможно, антивирус убрал `ym-bridge.dll` / `ym-bridge.dylib` в карантин. Восстановите файл или переустановите плагин из архива релиза и добавьте папку плагина в исключения антивируса |
| «Подпись библиотеки-моста не сошлась» | Переустановите плагин из архива релиза |
| «Клиент запущен от имени администратора» (Windows) | Снимите галочку «Запускать эту программу от имени администратора» в свойствах ярлыка клиента |
| Клиент в нестандартной папке | Укажите путь в панели настроек → «Соединение» → «Путь к клиенту» |
| Фиолетовые иконки | Перезапустите Stream Deck |
| Длинное нажатие не работает | Вероятно, ограничение вашего устройства (см. раздел "Громкость") |
| Discord-статус не появляется | Проверьте, что Discord запущен и включён переключатель Rich Presence |
| Обновление не доехало | Антивирус мог временно заблокировать файлы — плагин повторяет попытки и докатит обновление при следующем запуске. На Windows закройте Яндекс Музыку и перезапустите приложение Stream Deck. Если AV ругается на `ym-plugin.exe` или `ym-bridge.dll` — добавьте папку плагина в исключения. Ручная установка всегда работает как запасной вариант |
| Компьютера нет в списке на телефоне | Включите «Управление этим компьютером с телефона» в панели настроек → «Соединение»; на телефоне должен быть тот же аккаунт Яндекса. Если работало и перестало — возможно, Яндекс закрыл этот режим: проверьте обновление плагина |
| Управление пропало после обновления Яндекс Музыки | Обновите плагин до последней версии. Если не помогло — откройте [issue](https://github.com/Judd1zzz/yandex-music-streamdeck/issues) и приложите `plugin.log` из папки `logs/` плагина |
